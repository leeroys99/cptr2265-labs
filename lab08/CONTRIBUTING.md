# Branching Policy

For the rest of the semester, I will use GitHub Flow to organize my work and keep my main branch protected.

## Branches

- **main:** This branch will contain completed and reviewed work. Changes must go through a Pull Request and have at least one approval before merging.
- **develop:** This branch will be used to combine and test changes before moving them to main.
- **feature branches:** I will create a separate branch for new features or assignments instead of making changes directly to main.

## Pull Requests

When I finish working on a feature branch, I will push my changes to GitHub and create a Pull Request into develop. I will include a description of what I changed and request a review from a classmate.

## Merging Changes

After my changes have been reviewed, I will merge them into develop. When the work is ready, I will use another Pull Request to merge develop into main.

## Merge Conflicts

If a merge conflict happens, I will review the conflicting changes in VS Code, fix the problem, and test the files before committing and pushing the resolution.
